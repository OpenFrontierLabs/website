# Open Frontier Labs website

Frontend: static HTML + Tailwind v4 (no framework), plus a Worker (`worker/`, server-rendered HTML, no client JS) for sign-up and the consoles

- Source: pages `src/index.html`, `src/manifesto.html` (served at `/manifesto`), `src/404.html`; shared markup (icon sprite, nav, footer) in `src/partials/`, inlined by `<!--#partial name-->`; `src/styles.css`; static files in `public/` (including `_headers`); `scripts/build.ts` produces `dist/` with content-hashed CSS, fonts (Inter body, Michroma display caps) and art.
- Dashboard: `src/dashboard.html` (served at `/dashboard`) with its own stylesheet `src/dashboard.css` and icons `src/partials/sprite-dash.html`, so the home page doesn't carry them. Real values only: GitHub contributors and the latest merged PRs (build time), zeros elsewhere until Run 0 starts. The dotted world map `src/partials/world-dots.html` is generated by `bun scripts/world-map.ts` from Natural Earth (pinned). Its search box submits to GitHub, so `/dashboard` alone gets `form-action https://github.com` in `_headers`.
- Contributors: `src/contributors.html` (served at `/contributors`, own stylesheet `src/contributors.css`) is built from GitHub: users with commits in the org's three repos (avatars copied into `dist/assets`, bots left out), the compute ledger (`ledger/*.json` in openfrontier; files named `EXAMPLE` or marked `"example": true` are never rendered; empty state until a real file exists; handles and GPU-hours only) and `CREDITS.md` word for word. `tests/fixtures/github.json` records all of it for the tests, including the example ledger so the suite proves it never renders.
- Starter issues: `worker/starter.ts` maps questionnaire answers to contributor paths, each a live openfrontier issue search (`label:"good first issue"` plus an `area/*` or `layer/*` label; never issue numbers). The Overview shows them with the Discord invite, with a thank-you right after the questionnaire.
- Manifesto: `content/manifesto.md` is the one source, word for word the same as `MANIFESTO.md` in OpenFrontierLabs/openfrontier; the build renders it into both pages. Never edit its words here; change it upstream first, then copy.
- Stats: the build reads the GitHub contributor count and fails if GitHub refuses (no made-up 0); set `GITHUB_TOKEN` in the environment (never argv) when the anonymous rate limit bites.
- Speed: stylesheets are inlined (`<style>`) and admitted by SHA-256 in the CSP the build writes into `dist/_headers` and `worker/assets.gen.ts`; never add 'unsafe-inline' or a `<link rel="stylesheet">`. Fonts are not preloaded; metric-matched local fallbacks (`Inter Fallback`, `Michroma Fallback` in `src/styles.css`) keep the swap from shifting layout. Re-measure them if the fonts change. Lighthouse the live site on a quiet fleet host (load skews the CPU-bound metrics).
- Motion: CSS only (no scripts under the CSP), all inside `prefers-reduced-motion: no-preference`; scroll-driven effects sit behind `@supports (animation-timeline: view())`. Keyframe names must not clash with Tailwind's (`spin`, `ping`, `pulse`, `bounce`).
- Art: official brand PNGs live in `brand/` (source of truth; no redrawn logos). `bun run assets` (sharp) regenerates `art/` (AVIF/WebP/PNG, content-hashed by the build, referenced as `%ART:file%`) and the icons/OG in `public/`.
- Swarm: the coordinator (`ofl swarm coordinator --report-url`, openfrontier repo) POSTs nodes, runs and rounds to `/v1/swarm/ingest` (bearer `SWARM_INGEST_TOKEN`, a Worker secret; copy at `~/ofl-secrets/swarm-ingest-token`); `worker/swarm.ts` holds the D1 reads and writes, `worker/swarm-view.ts` the HTML. `GET /v1/swarm` is public JSON. `/dashboard` is a static asset whose `data-swarm` blocks the Worker fills from D1 per view (static zeros are the empty state and the fallback); the console's nodes, runs and contributions match nodes to the member by GitHub handle. Nodes count as online with a heartbeat in the last 2 minutes.
- App: `worker/index.ts` handles `/`, `/join*`, `/auth/*`, `/console*`, `/admin*`, `/logout`, `/__sentry-test` (`run_worker_first`); everything else is assets. Wrapped with `Sentry.withSentry` (`worker/sentry.ts`, server-side only, `nodejs_compat` in `wrangler.toml`) using Worker secrets `SENTRY_DSN` and `SENTRY_TEST_KEY` and deploy-injected `SENTRY_RELEASE` (git short SHA). GitHub OAuth (scope `read:user user:email`), HMAC-signed `__Host-` session cookie, D1 `ofl-waitlist` (`migrations/`), `audit` table for operator actions. Pages render in place: the only redirect is the OAuth hop to github.com. Routes are listed in `openapi.yaml`. `worker/assets.gen.ts` is generated by the build.
- Deploy target: Cloudflare Workers Static Assets + Worker (`wrangler.toml`). Deploy: `make release` (build, then remote D1 migrations and `wrangler deploy` under a one-hour token minted by the ms-01 broker, fudopro `tools/cf-token-broker`, venture `ofl`, plus debug-ID injection and sourcemap upload via `sentry-cli` when `~/.config/ofl/sentry.env` exists), run on a fleet host through `heavy-build-route --release`. The release host stores no deploy credential; only the broker's own token-minting token stays on ms-01.
- Check: `make check` (build, typecheck, oxlint, `bun test tests/site.test.ts tests/app.test.ts tests/swarm.test.ts tests/sentry.test.ts`). Always name the test files. Every commit needs a DCO `Signed-off-by` matching its author (`git commit -s`). Dependabot (`.github/dependabot.yml`) bumps actions and Bun packages weekly.

## Rules

- Bun only. No redirects of any kind (no `_redirects`, no redirect rules, no Worker redirects between our pages). Both domains are served directly.
- No crons, no KV/R2/queues/Durable Objects, no third-party client scripts (server-side `@sentry/cloudflare` in `worker/` only; browser CSP stays `script-src 'none'`). Workers + D1 only (sign-up and waitlist). $0 marginal cost.
- Strict CSP: no scripts, no `style` attributes; use classes. Worker pages set their own CSP (`worker/html.ts`); POSTs must carry our Origin.
- Content rule: no claims about results, traction, users, team size, funding, partnerships, endorsements or benchmarks. Anything not built is labelled "planned". No emoji. Email spelling is `openfrontierlabs@gmail.com` (with an i).
